# Route Meta 说明

项目里的路由大多会在 `meta` 里放菜单、权限、高亮和页面行为配置。常见写法如下：

```ts
meta: {
  requiresAuth: true,
  locale: 'menu.system',
  icon: 'icon-settings',
  order: 3,
  hideInMenu: false,
}
```

## 通用字段

### `requiresAuth`
- 是否需要登录后才能访问。
- 这是当前项目里最基础的字段，通常每个路由都应该显式声明。

### `roles`
- 允许访问当前路由的角色列表。
- 适合做角色级别的拦截，不适合替代更细的业务权限点。

### `locale`
- 菜单名称、面包屑名称使用的文案配置。
- 常见写法是字符串，比如 `locale: 'menu.system'`。

### `icon`
- 左侧菜单或菜单分组展示的图标名。

### `order`
- 菜单排序值。
- 一般值越大越靠前，具体顺序以项目当前菜单实现为准。

### `hideInMenu`
- 是否在左侧菜单中隐藏当前路由。
- 常用于详情页、编辑页、跳转页。

## 项目自定义字段

### `key`
- 项目里的菜单权限 key。
- 通常会和后端返回的菜单权限列表进行匹配，用来控制菜单显示、顶部按钮显示等。

### `routekey`
- 页面内部子导航 key。
- 常见于详情页左侧 tab、二级切换区域，用来标记当前激活的是哪个内部页面。

### `linkIcon`
- 是否在菜单后面展示“外链/跳转”样式图标。
- 当前项目里主要用于视觉提示，不等于真的会新开窗口。

### `menuGroup`
- 菜单所属分组。
- 这个字段适合用来代替“按路由名硬编码判断属于哪个菜单分组”的逻辑。
- 当前项目建议约定：
  - `cloudserver`：云服务相关
  - `system`：系统管理
  - `usermanage`：用户管理
  - `person`：个人中心
  - `topapp`：顶部应用类页面

## 使用建议

1. 详情页、编辑页优先配合 `hideInMenu + activeMenu` 使用，这样菜单高亮会更稳定。
2. 权限控制优先统一走 `meta.key`，避免同一套权限同时散落在多个地方判断。
3. 菜单分组如果后续继续重构，建议统一补 `meta.menuGroup`，减少 `router/index.ts` 里按路由名硬编码的逻辑。
